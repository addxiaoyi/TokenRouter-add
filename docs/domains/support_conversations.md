# 工单与客服会话

工单保存用户与客服之间的文字会话、处理状态和通知投递意图。身份验证沿用[身份与租户](identity_and_tenancy.md)，SMTP 连接沿用[通知与邮件投递](notification_delivery.md)。

<a id="ownership_and_workflow"></a>
## 权限与状态

| 操作 | 用户 | 管理员 |
| --- | --- | --- |
| 创建与读取 | 只能创建和读取自己的工单 | 管理入口可读取全部工单 |
| 回复 | 自己的未关闭工单 | 任意未关闭工单 |
| 状态 | 关闭、重新打开 | 待处理、处理中、已解决、已关闭 |
| 邮件设置 | 不可访问 | 收件人设置、投递统计、失败重试 |

用户身份来自认证上下文，客服身份由管理员路由固定。请求参数不能指定其他所有者或升级为客服。不存在和无权访问的工单均返回未找到，私有响应使用 `private, no-store`。

已解决工单收到用户回复后重新打开；客服回复进入处理中。已关闭工单需要先重新打开。状态写入携带版本号，冲突时客户端重新读取，避免覆盖另一位操作者的修改。

<a id="persistence_and_delivery"></a>
## 持久化与邮件

1. 创建和回复使用客户端 UUID 去重。同一 UUID 重试返回已提交结果；内容不一致返回冲突。创建时锁定用户记录，将待处理及处理中工单限制为 20 条。
2. 工单消息和邮件投递意图在同一事务提交，SMTP 故障不会丢失会话。用户回复通知 `support_ticket_recipients` 中的客服地址；客服回复通知工单所有者，迁移占位 `.invalid` 邮箱不投递。
3. Worker 领取持久通知，每个领取生成独立租约 UUID。旧任务的迟到结果不能确认新租约；手动重试同时更换租约标识，防止次数重置造成身份重用。
4. 邮件发送按至少一次处理。SMTP 已接受、数据库确认失败时可能重复发送。最多自动尝试十次，管理员修复 SMTP 后可重新排队；历史收件人保留提交时的值。

管理员未配置通知地址时，工单仍可提交并在后台处理。更改地址只影响后续消息。排查顺序为工单详情、通知待处理/失败数量、现有 SMTP 设置与投递日志。

<a id="legacy_import"></a>
## 旧站导入

1. 按唯一邮箱匹配所有者，必要时使用唯一用户名；无法唯一匹配时停止该条导入，不假设新旧用户 ID 相同。
2. `legacy_id` 和确定性消息 UUID 保证重复执行不会产生重复记录。原始标题、消息、客服回复及时间应保留。
3. 历史导入不生成通知意图，避免向用户重发旧消息。上线前在备份恢复环境验证迁移，回退旧二进制时保留新增表和已提交工单。
